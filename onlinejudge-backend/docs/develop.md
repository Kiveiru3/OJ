# Online Judge（类似洛谷）需求文档

## 1. 项目概述
- 项目名称：Online Judge
- 版本目标：`v1.0 (MVP)` / `v2.0`
- 项目背景：用于程序设计教学与训练，支持在线编程、自动评测、竞赛组织与学习交流。
- 核心目标（3 条以内）：
1. 提供稳定可用的做题与评测主链路。
2. 支持教师/管理员进行题库与竞赛管理。
3. 支持答辩场景的一键部署与可验证演示流程。

## 2. 目标用户与场景
- 目标用户：
1. 学生
2. 教师
3. 管理员
4. 游客（可选）

- 核心场景：
1. 学生刷题并查看评测结果
2. 教师发布/维护题目
3. 管理员管理用户与系统配置
4. 举办竞赛并生成榜单（v2 深化）

## 3. 范围定义
### 3.1 本期必须实现（MVP）
1. 用户系统：注册、登录、登出、个人信息
2. 题库系统：题目列表、筛选、题目详情
3. 提交评测：代码提交、状态查询、结果详情
4. 提交记录：我的提交列表、按条件筛选
5. 后台管理：题目管理、用户管理、系统配置与日志
6. 权限控制：游客/学生/教师/管理员

### 3.2 本期不做（明确排除）
1. 多机分布式评测调度
2. 复杂消息通知中心
3. 外部 SSO 登录

### 3.3 下期规划（v2）
1. 竞赛系统增强（封榜策略、题目气球等）
2. 题单系统
3. 讨论区与题解沉淀
4. 全站排行榜
5. 教学分析可视化增强

## 4. 角色与权限
| 角色 | 主要权限 |
|---|---|
| 游客 | 浏览公开题目（可选） |
| 学生 | 提交代码、查看自己的提交记录、维护个人资料 |
| 教师 | 创建/编辑题目、创建/编辑竞赛、查看教学分析 |
| 管理员 | 用户管理、题目删除、系统配置、操作审计 |

## 5. 功能需求（按模块）

### 5.1 用户系统
- 功能点：
1. 注册（用户名/邮箱/密码）
2. 登录（JWT）
3. 登出
4. 修改资料
5. 修改密码

- 验收标准：
1. 注册成功后可登录
2. 未登录访问受保护页面会跳转登录
3. Token 过期后自动清理会话并提示

### 5.2 题库系统
- 功能点：
1. 题目列表分页
2. 按难度/关键词筛选
3. 题目详情（描述、输入输出、样例）
4. 通过率/提交数展示

- 验收标准：
1. 列表支持分页与筛选联动
2. 题目详情加载稳定
3. 空数据有明确占位提示

### 5.3 提交与评测
- 功能点：
1. 选择语言并提交代码
2. 返回提交 ID
3. 查询评测状态（PENDING/JUDGING/AC/WA/TLE/RE/CE）
4. 查看耗时、内存、错误信息

- 验收标准：
1. 提交后能在提交记录中看到新记录
2. 评测状态可从等待推进到终态
3. 错误信息字段完整可读

### 5.4 提交记录
- 功能点：
1. 我的提交分页列表
2. 按题目/状态/语言筛选
3. 提交详情展示源码与评测结果

- 验收标准：
1. 列表与详情数据一致
2. 非本人不可查看他人私有提交（按权限规则）

### 5.5 题目管理（教师/管理员）
- 功能点：
1. 新建题目
2. 编辑题目
3. 删除题目（管理员）
4. 测试用例管理（样例/隐藏）

- 验收标准：
1. 新增后在题库可见
2. 编辑后实时生效
3. 删除具备二次确认与权限校验

### 5.6 用户管理（管理员）
- 功能点：
1. 用户分页列表
2. 角色查看/调整
3. 状态管理（禁用/启用）

- 验收标准：
1. 非管理员不可访问
2. 角色调整后权限及时生效

## 6. 业务规则
1. 每题限制：时间 `time_limit`，内存 `memory_limit`
2. 支持语言：`Java / C++ / Python`
3. 提交频率限制：默认每用户每分钟 20 次
4. 竞赛错误罚时：默认每次错误提交 20 分钟（可配置）
5. 题目可见性：公开/隐藏/竞赛内可见

## 7. 数据与接口约定
- 统一返回格式：
```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

- 分页参数约定：
1. `page` 从 1 开始
2. `size` 默认 10，最大 100

## 8. 非功能要求
1. 安全性：鉴权、越权拦截、接口限流、基础审计日志
2. 稳定性：评测超时可回收、关键流程可重试
3. 可扩展性：竞赛、评测、题库模块解耦
4. 可维护性：核心链路具备 smoke 测试脚本
